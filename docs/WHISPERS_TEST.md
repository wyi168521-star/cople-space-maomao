# 悄悄话实时聊天测试

访问 <http://192.168.0.212:3200/whispers>，也可从首页或时光轴的“悄悄话”入口进入。

## 双账号测试

使用 Chrome 与 Edge，或普通窗口与无痕窗口，分别登录同一个空间的账号 A、B。两个普通窗口通常共享登录状态，不能用来隔离两个账号。

1. 两边打开悄悄话，确认顶部显示对方昵称，连接状态为“已连接”。
2. A 输入消息并按 Enter；A 的消息靠右、淡紫色，B 应在不刷新页面的情况下看到左侧淡粉气泡。
3. B 保持聊天页面可见时，A 的消息会更新为“已读”。
4. B 输入第一行，按 Shift + Enter 换行，输入第二行再按 Enter；确认 A 收到两行文字，B 输入框清空且高度恢复。
5. B 先切换到时光轴，A 再发送消息；此时应显示“未读”。B 返回聊天后应收到该消息，A 随后变为“已读”。
6. 刷新页面确认历史仍在；消息较多时，顶部可加载更早记录。
7. 测试中文输入法：用于确认候选词的 Enter 不应误发消息。
8. 如需检查断线恢复，可在 B 的浏览器开发者工具 Network 中启用 Offline，A 发送消息后再取消 Offline；B 应重新连接并同步消息。

发送失败会显示原因并保留草稿。重试相同草稿会复用消息编号，避免保存成功但响应丢失时重复插入。已读同步失败有独立重试按钮，不会阻止消息显示。

打开并查看聊天时才标记收到的消息为已读；隐藏或关闭聊天页面期间不自动标记。

## 代码文件

- `app/composables/useWhispers.ts`：历史游标分页、发送、实时订阅、已读同步、异步请求及频道清理。
- `app/pages/whispers.vue`：气泡、输入框、键盘交互、滚动及连接状态界面。
- `app/utils/whisperState.ts`：按 ID 去重、微秒时间排序、已读状态合并和 LAN HTTP UUID 兼容。
- `app/styles/whispers.css`：聊天布局和移动端样式；气泡圆角、内边距、阴影使用 Tailwind 工具类。
- `supabase/migrations/20261030144521_whispers_realtime.sql`：将表加入 `supabase_realtime` 发布，保留原有 RLS。
- `tests/whisperState.test.ts`：消息合并、排序和 UUID 回归测试。

此迁移已经应用到本地数据库，当前开发服务器保持运行。迁移不改变数据表字段，因此无需重新生成类型。

部署到其他环境时，需要在那里应用迁移并配置对应 Supabase 地址及公开客户端 key。勿将本地环境文件或服务端密钥放入前端。
