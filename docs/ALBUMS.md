# 私有相册与瀑布流

- `/albums`：列表、封面、照片数量、新建相册。
- `/albums/:id`：相册详情、私有照片瀑布流、多选上传和大图预览。
- 列表位于 `app/pages/albums/index.vue`；详情位于 `app/pages/albums/[id].vue`。
  列表从原先的 `albums.vue` 移入目录，避免动态详情被当作没有 NuxtPage 出口的嵌套页面。

详情数据与上传由 `useAlbumDetails.ts` 管理：

1. 使用当前登录用户的情侣编号过滤相册，再分页读取该相册的 `album_media` 照片记录。
2. 复用私有媒体签名工具，最多四个并发请求，逐一调用 `createSignedUrl(path, 3600)`。
   不使用公开 URL，也不把签名写入浏览器持久缓存。页面停留较久时自动续签。
3. 文件逐张通过共享压缩入口的 `forceJpeg` 选项处理为 JPEG，最大边 1920px、质量 0.8，
   透明区域铺白。GIF 转成静态图片；HEIC 等浏览器无法解码的格式会提示转换后重试。
4. 存储路径为 `couple_id/albums/album_id/uuid.jpg`，上传至已有的 `couple-media` 私有桶。
5. 所有文件上传成功后，用稳定 UUID 批量插入 `album_media`，然后刷新照片墙。

文件上传失败或数据库明确拒绝写入时，尝试清理此次未关联的对象。若 INSERT 的返回结果
丢失，则按 UUID 查询记录确认；确认已保存时保留文件并展示成功。无法确认时保留对象，
提示先刷新检查，避免误删已关联文件或引导重复上传。Storage 与数据库不是同一事务，
断网或退出账号也可能导致清理失败，此时页面会给出提示（页面仍挂载时）。

图片使用 CSS columns 实现 2/3/4 列响应式瀑布流。加载失败时显示占位与重试按钮。
原生 dialog 提供全屏预览及焦点约束；Esc、点击背景和关闭按钮均可关闭。

验证结果：TypeScript 检查通过，60 项单元测试通过，本地 Supabase + Chrome 的
13 项联测通过，包含真实多图上传、JPEG 字节与尺寸、签名期限、全屏交互、失败清理、
丢失回包恢复、坏图提示、缺图重试、响应式布局、双方上传、RLS 隔离及返回列表更新。
所有临时测试账号、相册、数据库记录与存储对象已清理。
