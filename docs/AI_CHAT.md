# 与大毛聊聊

登录并加入空间后，首页右下角的“与大毛聊聊”打开聊天窗口。手机上使用全屏对话框，
桌面上使用右侧浮层，不改变首页卡片布局。

- Enter 发送；Shift + Enter 换行；中文输入法选字时不会误发送。
- 生成期间可点击“停止”；关闭窗口、离开首页或切换账号会取消正在进行的请求。
- 关闭后重新打开仍可查看本次首页内的对话；刷新、离开首页或切换账号后清空。
- “清空对话”立即清除当前聊天。聊天不写数据库或 localStorage。
- 接口失败时显示具体提示；尚未收到正文时显示带标识的本地暖心回复。
  已收到部分正文时保留并标注“回复未完成”，不会冒充完整回答。

## 配置与数据范围

复用私有 `NUXT_DEEPSEEK_API_KEY`（本地也兼容 `DEEPSEEK_API_KEY`）和
`NUXT_DEEPSEEK_MODEL`，当前默认 `deepseek-flash`。无需新增环境变量或数据库迁移。
浏览器只向同源 `/api/ai/chat` 发送 Supabase 会话和用户主动发送的聊天上下文。
接口验证真实用户及配对关系，再使用服务端密钥调用 DeepSeek。
不会自动读取悄悄话、照片、时光轴或其他情侣的内容。

大毛采用固定的“嘴硬心软、爱互怼、低落时可靠温柔”的人设。主回复最多 50 个
Unicode 字符（含标点），上游 `max_tokens: 150`，`thinking` 关闭，并以 SSE 返回。
单条用户消息最多 2000 字。新接口与每日情话、回忆日记共享每用户每 10 分钟
20 次功能调用的单实例限流；触发摘要的轮次会额外调用一次摘要模型。
生产多实例若需要严格统一限额，应将现有限流器迁移到共享存储。

## 滑动窗口与滚动摘要

- `allMessages` 保存本次首页内全部展示记录，不随摘要删除。
- `recentMessages` 保存已完整确认的最近轮次，最多 10 条，即五轮完整对话。
- `summary` 是最多 50 字的滚动摘要；聊天窗口中的“大毛记下的小事”可展开查看。
- 发起下一轮时加上新用户消息，临时提交至多 11 条。后端检测到超过 10 条，
  用 `max_tokens: 80`、非流式、低温度将“旧摘要 + 最旧四条”压缩成新摘要，
  然后以“固定 System + 记忆 User 消息 + 剩余窗口”生成主回复。
- 成功收到 `done` 才一起提交摘要和删窗确认，并把新回复加入工作窗口。
  摘要失败、主回复失败、断线或主动停止时，旧摘要和工作窗口保持不变；
  未完成回复与本地兜底仍显示在 `allMessages`，不会作为已确认记忆进入下一轮。
- 第六轮触发第一次整理，成功后工作窗口有 8 条；此后通常每两轮再整理一次。
  每次只是更新同一份 50 字摘要，避免摘要无限累加。

这是本次会话内的压缩记忆；刷新、清空、离开首页或切换账号后全部清空。
50 字摘要会舍弃细节，并不等同于完整、永久、无损的长期存储。
人设固定置于首条，摘要在两次整理之间保持不变，不注入时间戳等动态前缀。
DeepSeek 缓存自动开启，但是否命中及节省比例取决于实际请求，不保证固定节省 90%。
正常收到模型统计时，`done.usage` 和 `done.summaryUsage` 提供输入、输出与缓存命中
Token 数；到达 50 字硬限制提前取消上游时，主回复的最终统计可能缺失。
参考：[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)。

## 流式协议

`POST /api/ai/chat`，请求 JSON：

```json
{"recentMessages":[{"role":"user","content":"帮我们想个约会吧"}],"summary":""}
```

需要 `Authorization: Bearer <Supabase access token>`。
成功后返回 `text/event-stream`，每条事件以空行分隔：

```text
data: {"type":"delta","text":"一起"}

data: {"type":"delta","text":"去看晚霞吧。"}

data: {"type":"done","summary":"","trimmedCount":0}

```

流建立前的错误使用安全的 HTTP JSON 错误码，流建立后的异常使用
`{"type":"error","code":"AI_UNAVAILABLE"}` 等事件；不转发上游异常正文、密钥或思考过程。
客户端必须看到 `done` 才将回复视为完整。UTF-8 拆包、JSON 拆包、CRLF 与心跳均支持。
触发整理时，`done.summary` 为新摘要，`trimmedCount` 为 4；普通轮次则原样返回摘要、
`trimmedCount` 为 0。不会单独提前下发摘要，避免中断时出现双方记忆不一致。
客户端取消或断开连接后，后端取消上游请求，后端请求总时限为 45 秒。

Vercel 的 Nitro 函数配置为最多 60 秒，为前置会话校验与流式生成留出时间。
推送部署后可在未登录状态请求 `/api/ai/chat`，应返回 `401 / AUTH_REQUIRED`，
而不是旧版本的 `404`；真实生成还需要已登录且已配对的会话和服务端模型密钥。

本地测试需要 Supabase 正常运行，或明确配置为已建好的云端项目；
仅前端启动、数据库不可用时，会话与配对校验无法通过。
